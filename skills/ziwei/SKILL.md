# 紫微斗数解读

紫微读盘像接案一样先判断用户此问落在哪条宫位轴：命身、命财官迁、夫妻福德迁移、疾厄福德命宫、田宅父母，还是大限/流年牵动。

## 取盘

```
compute_chart("ziwei")
```

拿到十二宫（命宫/兄弟/夫妻/子女/财帛/疾厄/迁移/交友/官禄/田宅/福德/父母）、主星分布、四化、大限、身宫等。

## 先抓宫位轴

从 chart 读：
- `life_palace` → 命宫位置
- `body_palace` → 身宫位置
- `main_stars.<宫名>` → 各宫主星列表，空宫也是 `[]`
- `palaces_by_name.<宫名>` → 该宫完整资料（地支、主星、辅星、四化、大限）
- `si_hua` → 四化飞星（化禄/化权/化科/化忌）
- `five_element_bureau` → 五行局（决定起运年龄）
- `metadata.focus.life_palace` / `body_palace` → 命身宫三方四正聚合
- `metadata.focus.domains` → 事业、财帛、感情、健康等主题宫位三方四正
- `metadata.calibration_questions` → 紫微校盘追问

重点看命宫坐什么主星（紫微/天机/太阳/武曲/天同/廉贞/天府/太阴/贪狼/巨门/天相/天梁/七杀/破军/天魁/天钺等）。

但命宫只是入口，不是全部。先形成一个案眼：

- 事业案：命宫如何承接，官禄宫做什么，财帛宫怎样回报，迁移宫给不给外部平台。
- 感情案：夫妻宫是关系形态，福德宫是内在感受，迁移宫常显示外部环境和对象互动。
- 六亲案：对应宫位和命身、大限、四化同看，单宫星曜不够立断。
- 迁移案：迁移宫、命宫、官禄宫和大限宫要合看。

## 宫位解读

根据用户问题定位关键宫位：
- 事业 → **官禄宫**（主星 + 四化飞入情况）
- 感情 → **夫妻宫**
- 财运 → **财帛宫** + **田宅宫**
- 健康 → **疾厄宫**
- 人际 → **交友宫** + **迁移宫**
- 性格 → **命宫** + **福德宫**
- 父母/子女 → 对应六亲宫

看该宫的：
1. 主星是什么 → 基本格局
2. 有无四化飞入（化禄=机会，化权=掌控，化科=名声，化忌=阻碍）
3. 三方四正（对宫 + 两个夹宫）有无助力或冲克

优先使用 `metadata.focus.domains.<主题>` 和 `palaces_by_name.<宫名>`。事业至少看官禄宫、命宫、迁移宫、财帛宫的三方四正；感情至少看夫妻宫、福德宫、迁移宫；健康至少看疾厄宫、福德宫、命宫。

## 大限与流年

- `da_xian` → 当前大限走到哪个宫位
- 大限宫的主星 + 四化叠加先天盘 → 这十年的主旋律
- 流年盘叠加 → 今年具体走势

## 问诊与校盘

紫微对时辰敏感，精断时有校盘意识：

- 出生时间若来自家人记忆、整点、半点或可能误差超过 30 分钟，先问时间来源和可能误差。
- 要推过往经历时，问已发生的大事年份和事件类型，用来验证命身宫、大限宫、四化牵引。
- 问题若很泛，问一个主题焦点：事业、婚恋、迁移、六亲、健康，或当前最想验证哪件事。
- “你是不是孤独/强势/敏感”这类性格题容易被用户自我投射，证据价值低。

用户确认时间可能有误差时，用 `recompute_chart` 重算盘面。对比两份盘面的命身宫、主星分布差异，结合用户反馈的已发生事件判断哪份更吻合。

用户反馈只能帮助校盘和定焦点。最终断语仍要回到宫位、星曜、四化、大限和规则引用。

## 查引证

```
grep_classics("紫微|命宫|官禄", system="ziwei")
grep_rules("四化|化禄|化忌", system="ziwei")
```

挑 1-2 条相关典籍/规则佐证。

## 盘面阅读

输出前先回到 `compute_chart("ziwei")` 的 JSON：看命身宫、四化、`main_stars.<宫名>`、`palaces_by_name.<宫名>`、`metadata.focus` 和大限。按宫名取宫位（`palaces_by_name.官禄宫`），数组下标只是内部排盘顺序。

## 输出

- 先说本案宫位轴：为什么这个问题要看这些宫
- 再针对问题展开宫位分析
- 大限/流年的时间段标注清楚（"当前大限 XX-XX 岁，走 X 宫"）
- 四化影响用具体星名说明，不泛泛说"有化禄"
- 如果用户要精断，先问 `metadata.calibration_questions` 中的出生时间来源和 3 个已发生大事年份。
- 同一颗星落不同宫位含义不同，带宫位说话
